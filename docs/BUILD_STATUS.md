- Added public password-reset request and link-redemption pages, plus an authenticated Settings email-change form requiring the current password. New email addresses remain pending until the mailbox link is explicitly confirmed. Redemption does not occur on GET; scanners cannot consume a link by opening it.
- Links contain 256-bit random tokens in URL fragments, removed from browser history on page load. Only SHA-256 token hashes, expiry and purpose/account/auth-version/target-email metadata are stored in VerificationToken. Links expire after 30 minutes, are purpose-bound and single-use under a user-row lock. Success increments authVersion and deletes the user's outstanding account links. Password changes/device sign-out also invalidate older link versions; account deletion removes account-link records.
- Invalid/expired/reused links cannot mutate accounts. Email uniqueness failures roll back without consuming the link or changing either account. Reset responses avoid disclosing missing accounts; requests have a one-minute per-account/action send cooldown. JSON-only and same-origin checks protect the mutation endpoints. Public link pages have no-store/no-referrer/noindex headers.
- Added a configurable HTTPS delivery-service contract (Bearer-authenticated POST of to/subject/text, timeout and no redirects). No provider or credentials are bundled and live delivery is unverified. Explicit localhost-only local mode writes ignored test outbox files; ordinary API responses never expose links. Unconfigured delivery is reported clearly. Public deployment still needs edge rate protection and operational delivery monitoring.
